# AgentHub 移动端 App 功能取舍说明

本文档记录 AgentHub 移动端 App 相对 Web 端的功能取舍。当前结论：移动端首版不做 `今日协作` 区块，也不做 `版本、构建、部署` 相关操作。

## 1. 移动端首版定位

移动端 App 不复刻完整 Web 工作台，而是作为轻量协作入口：

- 查看工作区状态。
- 进入群聊/单聊。
- 向 Agent 发任务。
- 查看任务过程摘要。
- 查看产物摘要和必要详情。
- 查看 Agent 列表与基础状态。

Web 端继续承担完整工程工作台职责：

- 代码文件深度查看。
- 完整 diff。
- 完整预览。
- 版本保存。
- 构建。
- 部署。
- 高级 Agent 配置。

## 2. 明确不做：今日协作

### 2.1 原设计

首页原本包含 `今日协作` 区块，用于展示：

- 今日待处理任务。
- 截止时间。
- `去处理` 按钮。

### 2.2 当前结论

移动端首版删除 `今日协作` 区块。

### 2.3 删除原因

- 当前项目的核心不是日程/待办系统，而是多 Agent 工作区协作。
- `今日协作` 会让首页看起来像任务管理 App，削弱 AgentHub 的工作区与对话主线。
- 该区块需要额外的任务聚合逻辑，目前后端并没有独立 `/api/tasks` 这类稳定接口。
- workflow event、agent run、artifact review 等数据可以在工作区或聊天页里自然展示，不必单独抽成首页待办。

### 2.4 首页替代结构

删除后，首页建议保留：

- 顶部品牌区。
- 欢迎语。
- 总览指标：工作区数、运行中 Agent、产物数。
- 功能入口：群聊协作、工作区、代码/产物、Agent。
- 当前工作区卡片。
- 最新事件卡片。

这样首页更聚焦在“当前工作区发生了什么”和“我要进入哪里继续协作”。

## 3. 明确不做：版本、构建、部署

### 3.1 Web 端已有能力

Web 端代码工作区中已有 `版本、构建、部署` 能力，包括：

- 保存源码版本。
- 下载源码 zip。
- 构建静态产物。
- 发布到本地 latest 路由。
- 打开构建/部署预览。

对应接口包括：

- `POST /api/projects/:projectId/versions`
- `GET /api/projects/:projectId/source.zip?versionId=`
- `POST /api/projects/:projectId/builds`
- `POST /api/projects/:projectId/deploy`
- `/build-preview/*`
- `/deploy/*`

### 3.2 当前结论

移动端首版不做这些能力。

也就是说，App 端不提供：

- 保存版本按钮。
- 下载源码 zip 按钮。
- 开始构建按钮。
- 重新构建按钮。
- 发布部署按钮。
- 构建日志。
- 部署详情。
- latest 路由发布状态。

### 3.3 不做原因

- 版本、构建、部署属于工程交付链路，更适合 Web 端完整工作台。
- 移动端触发构建/部署容易产生误操作。
- 构建日志、失败原因、版本 diff 等信息在手机上阅读体验差。
- 真机 App 访问本地 preview / deploy 路由存在网络环境问题，例如手机上的 `127.0.0.1` 并不是开发电脑。
- 当前移动端首版应聚焦查看与协作，不承担发布动作。

### 3.4 App 中如何处理这些信息

移动端可以保留非常轻的“交付状态只读摘要”，但不提供操作。

例如在产物详情里展示：

- 最近一次源码包状态：仅显示 `已生成 / 未生成`。
- 最近一次构建状态：仅显示 `成功 / 失败 / 运行中`。
- 最近一次部署状态：仅显示 `成功 / 失败 / 无部署`。

如果需要操作，提供文案：

> 请在 Web 工作台完成版本、构建和部署。

## 4. App 端保留的代码/产物能力

删除 `版本、构建、部署` 后，App 的代码/产物页建议只保留这些内容：

### 4.1 文件摘要

展示：

- 文件路径。
- 文件类型。
- 行数或大小。
- 变更状态。

不做：

- 桌面级代码编辑。
- 完整 Monaco 编辑器。
- 文件写入。

### 4.2 Diff 摘要

展示：

- 修改文件数。
- 新增/删除行数。
- 关键文件列表。
- 简短变更摘要。

不做：

- 完整 patch 长文本。
- 复杂版本 diff。

### 4.3 预览摘要

展示：

- 预览产物是否 ready。
- 预览缩略图或链接。
- 必要时可用 WebView 打开。

不做：

- 构建触发。
- 部署触发。
- 完整 iframe 调试体验。

### 4.4 Review 摘要

展示：

- pass / partial / fail。
- 阻塞问题。
- 风险列表。
- 建议修改项。

这部分适合移动端保留，因为它能让用户快速判断当前产物是否可继续。

## 5. App 首页新版结构

删除 `今日协作` 后，首页建议为：

1. 品牌与通知区。
2. 欢迎区。
3. 三个指标卡：
   - 工作区数量。
   - 运行中 Agent。
   - 产物数量。
4. 全部功能入口：
   - 群聊协作。
   - 工作区。
   - 代码/产物。
   - Agent 管理。
5. 当前工作区卡片：
   - 工作区名称。
   - 主工作区标签。
   - 参与 Agent 头像。
   - 状态标签。
   - 最新事件。
6. 最近对话或最新事件列表。

## 6. App 底部导航建议

首版底部导航仍保留 5 个入口：

| Tab | 保留原因 |
| --- | --- |
| 首页 | 总览与当前工作区 |
| 工作区 | 切换、搜索、筛选工作区 |
| AI | 主对话入口 |
| 对话/代码 | 查看消息产物、文件摘要、diff 摘要、预览摘要 |
| 我的/Agent | Agent 列表与基础状态 |

其中 `对话/代码` 不再包含构建和部署操作。

## 7. App 与 Web 的职责边界

### 7.1 App 负责

- 快速查看状态。
- 快速进入对话。
- 跟踪 Agent 执行过程。
- 查看产物摘要。
- 查看 review 风险。
- 查看 Agent 状态。

### 7.2 Web 负责

- 深度代码查看。
- 完整 diff。
- 版本管理。
- 构建。
- 部署。
- 高级 Agent 配置。
- 长日志与复杂调试。

## 8. 后续 UI 生成要求

后续再生成移动端页面图时，应遵守：

- 首页不要出现 `今日协作`。
- 代码/产物页不要出现 `保存版本`、`开始构建`、`发布部署` 等按钮。
- 可以出现只读状态，例如 `最近构建：成功`，但不提供触发操作。
- 产物卡片重点展示 preview、diff、review、text。
- 整体仍保持背景图上色、玻璃卡片、底部胶囊导航的视觉方向。
