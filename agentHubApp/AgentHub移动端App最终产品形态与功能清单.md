# AgentHub 移动端 App 最终产品形态与功能清单

## 1. 文档目的

本文档只定义 AgentHub 移动端 App 的最终成品形态。

本文档回答四件事：

- 这个 App 最终应该是什么产品
- 这个 App 最终应该有哪些一级页面和二级页面
- 每个页面最终承载什么功能
- 哪些能力明确不属于移动端 App

本文档不讨论分阶段实施、不讨论先后顺序、不讨论接口接入节奏。

## 2. 产品定位

AgentHub 移动端 App 的最终定位是：

- 一个面向多 Agent 工作区的移动协作入口
- 一个随时查看任务状态、发起任务、跟进执行、查看产物和风险的工具
- 一个围绕“当前工作区”组织信息的 App，而不是按功能模块切碎的工具集合

AgentHub 移动端 App 不是：

- 桌面级完整工程工作台
- 代码编辑器
- 版本管理控制台
- 构建与部署控制台
- 长日志和深度调试工具

一句话定义：

> App 负责“随时看、随时问、随时跟”，Web 负责“深度改、深度验、正式交付”。

## 3. 最终成品形态

### 3.1 核心结构

最终 App 采用 3 个一级 Tab 结构：

| 一级页面 | 页面角色 | 核心职责 |
| --- | --- | --- |
| 工作台 | 全局入口 | 看工作区、切工作区、搜工作区、看最近变化 |
| 对话 | 主操作面 | 向工作区或 Agent 发任务，跟踪过程，看结果 |
| Agent | 能力面板 | 看 Agent 状态、资料、基础管理 |

### 3.2 产品组织原则

- App 的核心对象是“工作区”，不是“首页卡片集合”
- 对话是主操作面，不是附属页面
- 代码、预览、diff、review 都属于工作区内的二级详情能力，不再单独做一级 Tab
- 用户打开 App 后，应优先回到上次活跃工作区，而不是进入一个展示型首页
- 用户在手机上最重要的动作是：
  - 进入工作区
  - 发起任务
  - 跟进执行
  - 查看结果
  - 判断是否需要回到 Web 做深度操作

### 3.3 全局视觉与交互方向

- 整体是“工作区驱动”的专业协作产品，而不是营销型首页
- 视觉可延续当前玻璃卡片、背景图、轻层次发光的语言
- 但布局必须更克制，减少大面积展示型模块
- 首屏信息优先级必须围绕“当前工作区发生了什么”
- 顶部区域应简洁，避免大块欢迎语、装饰大图标、功能九宫格占据主空间

## 4. 页面结构

## 4.1 一级页面

### 工作台

工作台是 App 的全局入口页，不再单独保留一个与工作区脱节的“首页”。

页面结构：

- 顶部栏
- 当前活跃工作区卡片
- 工作区搜索与筛选区
- 置顶工作区列表
- 最近更新工作区列表
- 归档工作区入口
- 最近活动摘要

页面功能：

- 查看所有工作区
- 搜索工作区
- 筛选工作区状态
- 查看置顶与归档状态
- 查看每个工作区的运行状态、参与 Agent、最近事件、未读情况
- 创建新工作区
- 快速切换当前活跃工作区
- 进入任一工作区的对话页

页面不承担的职责：

- 不承担完整消息流阅读
- 不承担代码阅读主体
- 不承担版本、构建、部署操作

### 对话

对话页是 App 的主场景，也是整个产品的主操作面。

页面结构：

- 顶部工作区栏
- 群聊/单聊标识
- 工作区参与 Agent 概览
- 消息时间线
- 本轮过程卡
- 产物卡
- 底部输入区

页面功能：

- 查看当前工作区完整消息流
- 发送普通消息
- 在群聊中 `@Agent`
- 对某条消息进行引用回复
- 向工作区发起任务
- 跟踪任务执行过程
- 查看最终回复
- 从消息流中查看预览、diff、review、文本类产物摘要
- 打开工作区切换面板

对话页必须成为最终产品里最强的一页，承载以下体验：

- 群聊与单聊统一体验
- 流式回复
- 过程可视化
- 产物内联展示
- 失败与部分完成状态可见
- 用户不离开对话也能理解“刚刚发生了什么”

### Agent

Agent 页是移动端的能力面板，不是桌面级配置后台。

页面结构：

- 顶部筛选与搜索区
- Agent 状态摘要
- Agent 列表
- Agent 详情入口

页面功能：

- 查看所有内置 Agent 和自定义 Agent
- 查看 Agent 当前状态
- 查看 Agent 的角色、provider、model、技能标签、用途说明
- 进入 Agent 详情页
- 对自定义 Agent 做基础管理

移动端 Agent 页最终只做“轻管理”，不做“重配置”。

## 4.2 二级页面与抽屉

### 工作区切换与创建面板

这是对话页和工作台都会用到的全局面板。

功能：

- 快速切换工作区
- 创建群聊工作区
- 创建单聊工作区
- 选择目标 Agent
- 选择工作区类型

### 工作区详情页

工作区详情页用于展示当前工作区的背景信息，而不是消息流。

功能：

- 查看工作区名称、目标、类型、状态
- 查看参与 Agent
- 查看最近事件
- 查看运行中 Agent 数
- 查看产物数量
- 查看消息数量
- 置顶与取消置顶
- 归档与取消归档

### 产物详情页

产物详情页是移动端承接“代码 / 预览 / review / 交付摘要”的核心页面。

它不再作为一级 Tab 存在，而是从对话页中的产物卡或工作区详情进入。

页面结构：

- 预览摘要区
- 文件摘要区
- Diff 摘要区
- Review 结论区
- 交付状态摘要区

功能：

- 查看预览是否可用
- 查看预览缩略图、预览标题、预览说明
- 必要时打开 WebView 预览
- 查看变更文件列表摘要
- 查看新增/修改/删除行数摘要
- 查看关键文件清单
- 查看 review 结论
- 查看风险、阻塞项、修改建议
- 查看最近一次构建、部署、版本状态的只读摘要

### Agent 详情页

Agent 详情页用于承接移动端 Agent 轻管理。

功能：

- 查看 Agent 基础资料
- 查看角色说明
- 查看 provider 和 model
- 查看技能标签
- 查看最近参与的工作区和任务
- 编辑自定义 Agent 的基础字段
- 删除自定义 Agent

### 通知与活动中心

这是全局二级页，不作为一级 Tab。

功能：

- 查看提及我的消息
- 查看工作区运行完成事件
- 查看 review 失败事件
- 查看预览就绪事件
- 查看工作区最近活动列表

它的作用不是替代工作区，而是帮助用户在多工作区场景里快速发现需要处理的地方。

## 5. 最终功能清单

## 5.1 工作区能力

- 工作区列表查看
- 工作区搜索
- 工作区状态筛选
- 工作区置顶
- 工作区归档
- 工作区创建
- 群聊工作区与单聊工作区区分
- 当前工作区切换
- 记住上次活跃工作区
- 查看工作区参与 Agent
- 查看工作区最新事件
- 查看工作区未读状态
- 查看工作区运行状态

## 5.2 对话协作能力

- 群聊消息流
- 单聊消息流
- 用户消息发送
- Agent 回复展示
- 流式回复展示
- `@Agent` 提及
- 引用回复
- 文件引用入口
- 工作区级上下文对话
- 最终回复与过程信息同屏呈现

## 5.3 过程可视化能力

- 路由完成状态
- Agent 已派发状态
- Agent 执行中状态
- Review 等待中状态
- Review 已完成状态
- Partial / Failed / Success 状态展示
- 本轮过程展开与折叠
- 按轮次查看任务过程
- 用结构化卡片展示过程，而不是长文本日志

## 5.4 产物能力

- 预览产物摘要
- Diff 产物摘要
- Review 产物摘要
- 文本类产物摘要
- 文件变更摘要
- 风险与阻塞项摘要
- 预览详情查看
- 可用时通过 WebView 或外部链接打开预览
- 最近一次构建状态只读展示
- 最近一次部署状态只读展示
- 最近一次版本状态只读展示
- 复制产物摘要内容

## 5.5 Agent 能力

- Agent 列表查看
- Agent 搜索
- Agent 状态筛选
- 查看内置 Agent 资料
- 查看自定义 Agent 资料
- 查看 Agent provider
- 查看 Agent model
- 查看 Agent 技能标签
- 查看 Agent 最近参与情况
- 创建自定义 Agent
- 编辑自定义 Agent 的基础信息
- 删除自定义 Agent

移动端允许编辑的字段建议限定为：

- 名称
- 角色描述
- 简介
- provider
- model
- 技能标签

## 5.6 全局系统能力

- 上次活跃工作区恢复
- 后端连接状态展示
- SSE 连接状态展示
- 加载中状态页
- 空状态页
- 错误状态页
- 重试机制
- 下拉刷新
- 通知与活动中心
- 未读和提及提醒

## 6. 页面级功能定义

## 6.1 工作台页最终长相

工作台页不应该是“一个大而散的首页”，而应该像“移动版工作区总览台”。

最终页面应包含：

- 简洁顶部栏
- 当前活跃工作区主卡
- 工作区搜索框
- 筛选与排序入口
- 置顶工作区列表
- 最近更新工作区列表
- 归档入口
- 最近活动摘要条目

最终页面不应包含：

- 大面积欢迎区占主屏
- 展示型功能九宫格作为页面主体
- 与当前工作区无关的装饰型信息块

## 6.2 对话页最终长相

对话页要像“移动版工作区主控台”。

最终页面应包含：

- 当前工作区标题
- 群聊/单聊标识
- 参与 Agent 概览
- 消息时间线
- 过程卡
- 产物卡
- 输入区
- `@Agent` 入口
- 引用回复条

最终页面不应包含：

- 桌面式三栏结构
- 单独右侧诊断栏
- 长 stdout/stderr 原文滚动展示
- 深度代码编辑器

## 6.3 产物详情页最终长相

产物详情页是移动端取代“独立代码页”的核心。

最终页面应包含：

- 预览摘要与打开入口
- 文件列表摘要
- Diff 摘要
- Review 结论
- 风险与阻塞项
- 交付状态只读摘要

最终页面不应包含：

- 完整 patch 阅读体验
- 版本对版本复杂比对
- 构建或部署操作按钮
- 长日志调试界面

## 6.4 Agent 页最终长相

Agent 页应是一页“轻量能力面板”。

最终页面应包含：

- Agent 搜索
- 状态筛选
- 列表卡片
- 基础资料
- 详情入口

最终页面不应包含：

- 桌面式复杂表单
- 大段 system prompt 编辑
- routingProfile 全量编辑
- 权限矩阵和复杂隔离策略配置

## 7. 明确不属于移动端 App 的能力

以下能力即使在最终产品里，也明确不纳入移动端 App：

- Monaco 代码编辑器
- 完整文件树编辑
- 完整 patch diff 阅读
- 版本保存
- 版本比较
- 版本恢复
- 源码 zip 下载
- 构建触发
- 重新构建触发
- 部署触发
- 长构建日志
- 长部署日志
- 深度诊断日志面板
- 高级 Agent 配置
- 桌面式多面板工作台

以下能力可以在 App 中以“只读摘要”形式出现，但不提供操作入口：

- 最近一次版本状态
- 最近一次构建状态
- 最近一次部署状态
- 最近一次预览状态

## 8. 最终产品判断标准

当移动端 App 达到以下状态时，可以认为它已经具备明确的最终产品形态：

- 用户能在手机上快速找到并切换工作区
- 用户能在手机上直接向工作区或指定 Agent 发任务
- 用户能看懂一次任务当前走到了哪一步
- 用户能直接在对话中看到产物与审查结果
- 用户能判断“现在可以继续推进”还是“必须回 Web 深度处理”
- 用户能在手机上完成协作跟进，而不是只能看一个静态展示 Demo

最终成品的目标不是让用户“在手机上做完所有工程动作”。

最终成品的目标是：

> 让用户在不打开电脑的情况下，也能完成一次有效的多 Agent 协作跟进。
