# AgentHub 业务后端接口文档

本文档定义 `agentHubBackend` 对前端提供的业务接口。目标是让前端只依赖业务后端，由业务后端统一封装 AgentHub Runtime、业务项目状态、消息历史、事件流、产物、版本、构建和部署。

业务后端默认端口：

```text
http://127.0.0.1:8790
```

AgentHub Runtime 默认端口：

```text
http://127.0.0.1:8787
```

## 1. 设计定位

业务后端是产品层入口，不直接替代 AgentHub Runtime。

```text
Frontend
  -> agentHubBackend:8790
    -> AgentHub Runtime:8787
    -> local metadata storage
    -> local artifact storage
    -> build / deploy jobs
```

边界划分：

| 层级 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| Frontend | 工作台 UI、交互状态、SSE 展示、预览入口 | 不直连 AgentHub Runtime，不维护业务持久化 |
| agentHubBackend | 项目、会话、消息、事件、Agent 列表、产物、版本、构建、部署 | 不实现 Agent 编排核心，不直接执行模型调度 |
| AgentHub Runtime | 主脑路由、子 Agent 执行、workspace repo、workflow events、预览、zip | 不暴露产品级 project/build/deploy 语义 |

核心原则：

- 前端只认业务后端 `/api`。
- 业务后端内部维护 `projectId -> workspaceId` 映射。
- `state` 是前端聚合读模型，不是唯一事实来源。
- `workflow_events` 是工作流事实流，需要可实时订阅，也需要可历史查询。
- 构建和部署从一开始按异步 job 模型设计，避免同步 HTTP 长时间阻塞。

## 2. 核心概念

| 概念 | ID 示例 | 说明 |
| --- | --- | --- |
| Project | `proj-xxx` | 业务项目，前端展示为“工作区”。 |
| Runtime Workspace | `ws-xxx` | AgentHub Runtime 执行空间，包含 repo、预览和 zip。 |
| Conversation | `conv-xxx` | 项目下的会话，可为群聊或单聊。 |
| Agent | `engineer` | 可被选择、调度或自定义的 Agent。 |
| Message | `msg-xxx` | 用户、Agent、系统消息。 |
| Workflow Event | `evt-xxx` | 编排、派发、执行、审查、产物生成等过程事件。 |
| Artifact | `artifact-xxx` | 预览、源码包、文本摘要、diff、构建结果等产物。 |
| Version | `v1.0.0` | 固化后的源码版本。 |
| Build Job | `build-xxx` | 异步构建任务。 |
| Deployment | `deploy-xxx` | 发布记录。 |

项目和 Runtime 的关系：

```text
projectId -> workspaceId -> runtime repo
```

会话和消息的关系：

```text
projectId
  -> conversations[]
    -> messages[]
    -> workflow_events[]
```

## 3. 落地优先级

接口状态使用以下标记：

| 状态 | 含义 |
| --- | --- |
| P0 | MVP 必须实现，支撑前端完整 live 工作台。 |
| P1 | 第二阶段增强，支撑自定义 Agent、文件管理和更完整历史查询。 |
| P2 | 交付增强，支撑版本、构建、部署和发布记录。 |
| Runtime 已有 | AgentHub Runtime 已提供能力，业务后端需要封装或代理。 |

推荐实现顺序：

```text
1. health
2. agents list
3. projects create/list/detail/state
4. conversations list/create
5. project message stream
6. project events history
7. project artifacts and workspace zip
8. custom agents and file read/write
9. versions/builds/deployments as async jobs
```

## 4. P0 MVP 接口

P0 目标是让前端能完成基础闭环：

```text
进入工作台
  -> 获取项目列表
  -> 获取 Agent 列表
  -> 创建项目
  -> 进入单聊或群聊
  -> 发送消息
  -> 接收 workflow SSE
  -> 刷新项目 state
  -> 展示事件、消息、Agent 执行状态、产物和预览
```

### 4.9 流式发送消息

| 状态 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| P0 | `POST` | `/api/projects/:projectId/messages/stream` | 向项目会话发送消息，并返回 workflow SSE。 |

请求：

```json
{
  "conversationId": "conv-xxx",
  "content": "帮我做一个投票页面",
  "agentId": "engineer"
}
```

字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `conversationId` | `string` | 否 | 不传时使用项目默认会话。 |
| `content` | `string` | 是 | 用户消息内容。 |
| `agentId` | `string` | 否 | 单聊或定向 @ Agent 时传入。 |

业务后端内部行为：

```text
projectId -> workspaceId
conversationId -> runtime conversationId
POST AgentHub Runtime /api/messages/stream
  body: { workspaceId, conversationId, content, agentId }
```

SSE 返回格式：

```text
event: workflow_event_type
data: {"type":"workflow_event_type","workspaceId":"ws-xxx","conversationId":"conv-xxx"}
```

要求：

- 业务后端需要把 SSE 原样转发给前端。
- 业务后端需要持久化关键 workflow event，便于刷新后恢复右侧任务链路。
- SSE 结束后，前端可再请求 `GET /api/projects/:projectId/state` 刷新最终状态。

### 5.3 文件接口

文件接口面向 Runtime workspace repo。P1 先提供只读和受控写入，不直接暴露任意绝对路径。

| 状态 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| P1 | `GET` | `/api/projects/:projectId/files` | 获取 workspace 文件树。 |
| P1 | `GET` | `/api/projects/:projectId/files?path=src/App.tsx` | 读取指定文件内容。 |
| P1 | `PUT` | `/api/projects/:projectId/files` | 写入 workspace 文件。 |

写文件请求：

```json
{
  "filePath": "src/App.tsx",
  "content": "文件内容"
}
```

写文件响应：

```json
{
  "filePath": "src/App.tsx",
  "workspaceId": "ws-xxx",
  "updatedAt": "2026-05-27T00:00:00.000Z"
}
```

约束：

- `filePath` 必须是 workspace repo 相对路径。
- 禁止 `..`、绝对路径和 `.git` 目录写入。
- 写入后建议追加 `artifact_created` 或 `change_set_created` 事件，方便前端刷新。

## 6. P2 版本、构建和部署

P2 目标是形成完整交付链路。不要把构建和部署做成同步接口，统一按异步 job 设计。

### 6.1 版本

版本用于把当前 Runtime workspace repo 固化成可追踪源码快照。

| 状态 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| P2 | `POST` | `/api/projects/:projectId/versions` | 保存当前源码版本。 |
| P2 | `GET` | `/api/projects/:projectId/versions` | 获取版本列表。 |
| P2 | `GET` | `/api/projects/:projectId/versions/:versionId` | 获取版本详情。 |
| P2 | `GET` | `/api/projects/:projectId/diff?v1=v1.0.0&v2=v1.0.1` | 获取两个版本 diff。 |
| P2 | `GET` | `/api/projects/:projectId/source.zip?versionId=v1.0.0` | 下载版本源码包。 |

保存版本请求：

```json
{
  "versionId": "v1.0.0",
  "message": "保存第一个可交付版本",
  "requireAgentGate": true
}
```

```json
{
  "version": {
    "versionId": "v1.0.0",
    "projectId": "proj-xxx",
    "workspaceId": "ws-xxx",
    "tag": "v1.0.0",
    "commitSha": "abc123",
    "sourceZipUrl": "/api/projects/proj-xxx/source.zip?versionId=v1.0.0",
    "agentGate": {
      "status": "pass",
      "reviewVerdict": "pass",
```

## 8. 错误响应

所有 JSON 接口错误响应统一为：

```json
{
  "error": {
    "code": "PROJECT_NOT_FOUND",
    "message": "Project not found: proj-xxx",
    "details": {}
  }
}
```

常见状态码：

| 状态码 | 场景 |
| --- | --- |
| `400` | 请求字段不合法。 |
| `404` | 项目、会话、Agent、版本、构建不存在。 |
| `409` | 状态冲突，例如构建中不能删除版本。 |
| `422` | 请求语义合法但无法执行，例如未通过 Agent gate。 |
| `500` | 业务后端内部错误。 |
| `502` | AgentHub Runtime 不可用。 |

SSE 错误事件：

```text
event: error
data: {"error":{"code":"RUNTIME_STREAM_FAILED","message":"AgentHub Runtime stream failed"}}
```

## 9. 数据存储建议

MVP 阶段可以使用本地 JSON 和本地 artifact 目录：

```text
storage/projects/{projectId}/metadata.json
storage/projects/{projectId}/events.jsonl
storage/projects/{projectId}/messages.jsonl
storage/artifacts/source/{projectId}/{versionId}.zip
storage/artifacts/build/{projectId}/{versionId}
storage/deploy/{projectId}/latest
```

正式阶段建议迁移到 PostgreSQL，只存元数据，不存大文件：

```text
projects
project_workspaces
agents
conversations
messages
workflow_events
artifacts
versions
build_jobs
deployments
```

文件和产物仍然放本地磁盘、NAS 或对象存储。

## 10. 当前落地结论

第一版不要追求完整发布平台，先做 P0：

```text
GET  /api/health
GET  /api/agents
GET  /api/projects
POST /api/projects
GET  /api/projects/:projectId
GET  /api/projects/:projectId/state
GET  /api/projects/:projectId/conversations
POST /api/projects/:projectId/conversations
POST /api/projects/:projectId/messages/stream
GET  /api/projects/:projectId/conversations/:conversationId/messages
GET  /api/projects/:projectId/events
GET  /api/projects/:projectId/conversations/:conversationId/events
GET  /api/projects/:projectId/artifacts
GET  /api/projects/:projectId/workspace.zip
```

这组接口完成后，前端就可以完整切到业务后端：

```text
创建工作区
  -> 选择单聊/群聊
  -> 选择 Agent
  -> 发送消息
  -> 展示消息历史
  -> 展示 workflow events
  -> 展示 Agent 执行状态
  -> 查看预览和下载源码包
```

P1 再补自定义 Agent、项目编辑、会话管理和文件接口。P2 再补版本、构建和部署 job。
