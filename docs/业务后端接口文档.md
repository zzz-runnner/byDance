# AgentHub 业务后端接口文档

本文档按当前 `agentHubBackend` 的 NestJS Controller 和 DTO 整理，只记录已经实现的业务后端接口。

默认地址：

```text
业务后端: http://127.0.0.1:8790
AgentHub Runtime: http://127.0.0.1:8787
```

## 通用约定

- 所有 `/api/**` JSON 接口默认使用 `Content-Type: application/json`。
- 流式消息接口返回 `text/event-stream; charset=utf-8`。
- zip、预览、构建产物、部署产物接口返回文件或静态资源内容。
- 时间字段均为 ISO 字符串。
- 全局启用 Nest `ValidationPipe`，会自动转换查询参数类型，并拒绝 DTO 外的字段。
- 当前没有鉴权层。
- JSON 错误默认使用 Nest 结构，例如：

```json
{
  "message": "Project not found: proj-xxx",
  "error": "Not Found",
  "statusCode": 404
}
```

运行时 AgentHub 连接失败会返回 `503 Service Unavailable`；Runtime 已返回的非 2xx JSON 状态会按原状态码透传。

## 二、Agent 管理

Agent 接口由业务后端代理到 AgentHub Runtime。当前分为两类：

- 全局 `/api/agents` 用于读取内置 Agent 模板列表和详情。
- 项目级 `/api/projects/:projectId/agents` 用于管理某个项目 workspace 内可见的 Agent，支持创建、编辑、删除工作区自建 Agent，也支持对内置 Agent 做工作区级名称和模型覆盖。

Agent 常用字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | Agent ID。创建时可选，不传由 Runtime 生成。 |
| `name` | `string` | Agent 名称。 |
| `role` | `string` | 角色定位。 |
| `description` | `string` | 描述。 |
| `whenToUse` | `string` | 何时调用。 |
| `systemPrompt` | `string` | 系统提示词。 |
| `modelProvider` | `claude \| codex \| mock` | 模型提供方。 |
| `model` | `string` | 模型名，可选。 |
| `contextPolicy` | `object` | 上下文策略。 |
| `tools` | `string[]` | 工具列表。 |
| `permissions` | `object` | 文件、shell、网络、部署权限。 |
| `disallowedTools` | `string[]` | 禁用工具，可选。 |
| `permissionMode` | `readonly \| ask \| acceptEdits \| dangerous` | 权限模式。 |
| `runtimePolicy` | `object` | 运行策略。 |
| `outputSchema` | `string` | 输出约束。 |
| `isolation` | `shared \| worktree` | 隔离模式。 |
| `skills` | `string[]` | 技能列表。 |
| `routingProfile` | `object` | 路由画像，可选。 |
| `source` | `built-in \| workspace` | Agent 来源。 |
| `workspaceId` | `string` | 工作区级自建 Agent 所属 workspace，可选。 |
| `createdAt` / `updatedAt` | `string` | 创建和更新时间。 |

### GET `/api/agents`

返回全局内置 Agent 模板列表。

响应：

```json
[
  {
    "id": "engineer",
    "name": "工程师 Agent",
    "modelProvider": "codex",
    "source": "built-in",
    "createdAt": "2026-06-01T09:00:00.000Z",
    "updatedAt": "2026-06-01T09:00:00.000Z"
```

兼容保留路由。当前 Runtime 不再允许通过全局接口编辑 Agent，调用会返回 `400`，前端应使用 `PATCH /api/projects/:projectId/agents/:agentId`。

响应：

```json

}
```

兼容保留路由。当前 Runtime 不再允许通过全局接口删除 Agent，调用会返回 `400`，前端应使用 `DELETE /api/projects/:projectId/agents/:agentId`。

## 三、项目级 Agent 管理

这些接口会先根据 `projectId` 找到业务项目绑定的 Runtime workspace，再代理到 Runtime 的 workspace Agent 接口。

### GET `/api/projects/:projectId/agents`

返回当前项目 workspace 内可见的 Agent 列表，包括内置 Agent 的工作区级展示形态和该 workspace 内自建的 Agent。

响应：`AgentDefinition[]`。

### GET `/api/projects/:projectId/agents/:agentId`

返回当前项目 workspace 内的单个 Agent。

### POST `/api/projects/:projectId/agents`

在当前项目 workspace 内创建自建 Agent，并同步更新工作区群聊成员。

请求字段与 `CreateAgentDto` 一致，常用示例：

```json
{
  "id": "qa-agent",
  "name": "测试专家",
  "role": "QA Engineer",
  "description": "负责测试和验收",
  "whenToUse": "需要测试、验收或质量把关时调用",
  "systemPrompt": "你是一个严格的软件测试专家。",
  "modelProvider": "codex",
  "model": "default",
  "permissions": {
    "fileRead": true,
    "fileWrite": false,
    "shell": false,
    "webSearch": false,
    "webFetch": false,
    "deploy": false
  }
}
```

必填字段：`name`、`systemPrompt`。

响应：创建后的 AgentDefinition，通常包含：

```json
{
  "id": "qa-agent",
  "name": "测试专家",
  "source": "workspace",
  "workspaceId": "ws-xxx",
  "createdAt": "2026-06-01T10:00:00.000Z",
  "updatedAt": "2026-06-01T10:00:00.000Z"
}
```

### PATCH `/api/projects/:projectId/agents/:agentId`

编辑当前项目 workspace 内的 Agent。

内置 Agent 在工作区内只支持覆盖这些字段：

```text
name, modelProvider, model
```

工作区自建 Agent 支持编辑：

```text
name, modelProvider, model, role, description, whenToUse, systemPrompt,
contextPolicy, tools, permissions, disallowedTools, permissionMode,
runtimePolicy, outputSchema, isolation, skills, routingProfile
```

响应：更新后的 AgentDefinition。

### DELETE `/api/projects/:projectId/agents/:agentId`

删除当前项目 workspace 内的自建 Agent，并同步更新工作区群聊成员。

响应：

```json
{
  "deleted": true,
  "agentId": "qa-agent",
  "workspaceId": "ws-xxx"
}
```

限制：内置 Agent 不可删除。

```json
  "conversationType": "group",
```

字段：

| `conversationId` | `string` | 否 | 绑定已有 Runtime conversation。 |

## 五、项目运行态、文件和消息

### GET `/api/projects/:projectId/state`

获取单个项目对应 workspace 的前端聚合状态。

查询参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `messageLimit` | `number` | `40` | 返回最近消息数量，最大 200。 |

响应：

```json
{
  "state": {
    "workspaces": [],
    "conversations": [],
    "messages": [],
    "agents": [],
    "workspaceAgentMembers": [],
    "agentSessions": [],
    "agentSessionMessages": [],
    "taskHandoffs": [],
    "agentRuns": [],
    "artifacts": [],
    "changeSets": [],
    "contextSnapshots": [],
    "workflowEvents": [],
    "diagnosticLogs": []
  },
  "messagePage": {
    "limit": 40,
    "total": 120,
    "hasMore": true
  }
}
```

说明：

- `state` 是 Runtime 全局状态过滤到当前项目 workspace 后的结果。
- `state.workspaces[]` 会补充 `projectId`、`agentHubPreviewUrl`、`agentHubZipUrl`、`pinnedAt`、`archivedAt`。
- `state.workspaceAgentMembers[]` 是当前 workspace 的 Agent 成员关系，用于恢复内置 Agent 的工作区级名称、模型覆盖和排序状态。
- 当前没有单独的会话列表、消息历史、事件历史接口；前端从 `state` 读取这些数据。

### GET `/api/projects/:projectId/files/preview?path=docs/report.docx`

读取一个可预览文档文件的轻量预览数据。当前支持 PDF、Word、PowerPoint：

```text
pdf | docx | pptx
```

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `path` | `string` | 是 | workspace repo 相对路径。 |

响应：

```json
{
  "kind": "docx",
  "path": "docs/report.docx",
  "name": "report.docx",
  "byteLength": 12345,
  "updatedAt": "2026-06-01T10:00:00.000Z",
  "sourceUrl": "/preview/runtime/proj-xxx/docs/report.docx",
  "summary": "Word 预览提取了 12 段正文内容。",
  "textContent": "文档正文摘要",
  "sections": [
    {
      "title": "Paragraph 1",
      "content": "第一段内容"
    }
  ]
}
```

说明：

- PDF 返回原文件内嵌预览所需的 `sourceUrl`，通常没有 `sections`。
- DOCX/PPTX 会从 Office XML 中提取有限数量的纯文本段落或幻灯片文本。
- 当前单文件最大预览大小为 16MB。

### POST `/api/projects/:projectId/change-sets/:changeSetId/apply`

把 Runtime 已记录的一个 change set patch 应用到当前 workspace repo。该接口会从 Runtime state 中查找属于当前项目 workspace 的 `changeSetId`，并把其文本 patch 应用到本地工作区。

响应：

```json
{
  "status": "applied",
  "changeSetId": "change-xxx",
  "summary": "Applied patch successfully."
}
```

`status` 枚举：

```text
applied | already_applied
```

限制：change set 必须包含可应用的文本 patch；找不到 change set 或 patch 为空时会返回错误。

响应：同 `GET /api/projects/:projectId/preview-capability`。

### POST `/api/projects/:projectId/messages/stream`

向项目会话发送消息，并原样转发 AgentHub Runtime SSE。

请求：

```json
{
  "conversationId": "conv-xxx",
  "content": "帮我实现投票页面",
  "agentId": "engineer",
  "replyTo": {
    "messageId": "msg-xxx",
    "senderId": "engineer",
    "senderName": "工程师 Agent",
    "excerpt": "上一条消息摘要"
  },
  "codeSelection": {
    "filePath": "src/App.tsx",
    "selectedText": "function App() {}",
    "startLine": 1,
    "startColumn": 1,
    "endLine": 1,
    "endColumn": 18,
    "language": "typescript",
    "beforeContext": "",
    "afterContext": ""
  }
}
```

字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `content` | `string` | 是 | 用户消息，最长 20000。 |
| `conversationId` | `string` | 否 | 不传时使用项目默认 `conversationId`。 |
| `agentId` | `string` | 否 | 指定目标 Agent。 |
| `replyTo` | `object` | 否 | 回复引用。 |
| `codeSelection` | `object` | 否 | 代码选区引用；未指定 Agent 时会优先路由给 `engineer`。 |

响应：SSE。

```text
event: assistant_delta
data: {"type":"assistant_delta","workspaceId":"ws-xxx","conversationId":"conv-xxx"}
```

业务后端会解析 SSE 中的 JSON `data`，把关键 workflow summary 写回项目元数据，包括最新 change set、preview、验收状态、review 结论和 workflow 完成时间。

### PUT `/api/projects/:projectId/messages/:messageId/pin`

把一条已持久化的 Runtime 消息加入当前 workspace 的长期上下文 pin 列表。后续 Agent 上下文会读取 `workspace.pinnedMessageIds`。

响应：

```json
{
  "workspaceId": "ws-xxx",
  "messageId": "msg-xxx",
  "pinnedMessageIds": ["msg-xxx"]
}
```

限制：Runtime 会校验 `messageId` 属于当前 workspace；找不到消息时返回 `404`。

### DELETE `/api/projects/:projectId/messages/:messageId/pin`

从当前 workspace 的长期上下文 pin 列表中移除一条消息。

响应：

```json
{
  "workspaceId": "ws-xxx",
  "messageId": "msg-xxx",
  "pinnedMessageIds": []
}
```

### POST `/api/projects/:projectId/builds`

构建指定版本。当前接口是同步执行，不是异步 job 列表接口；成功或失败都会回写版本的构建字段。

请求：

```json
{
  "versionId": "v1.0.0",
  "skipDocker": false,
  "installCommand": "npm install",
  "buildCommand": "npm run build"
}
```

字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `versionId` | `string` | 否 | 不传时使用 `currentVersionId`。 |
| `skipDocker` | `boolean` | 否 | 为 `true` 时跳过 Docker 容器构建，改用宿主机执行安装和构建命令。 |
| `installCommand` | `string` | 否 | 安装命令。Docker 构建默认 `npm install`；宿主机构建会按 lockfile 推断，兜底 `npm install`。 |
| `buildCommand` | `string` | 否 | 构建命令，默认 `npm run build`。 |

响应：更新后的 ProjectVersionRecord。

```json
{
  "versionId": "v1.0.0",
  "tag": "v1.0.0",
  "commitSha": "abc123",
  "sourceZipUrl": "/api/projects/proj-xxx/source.zip?versionId=v1.0.0",
  "buildPath": "D:\\...\\data\\artifacts\\build\\proj-xxx\\v1.0.0",
  "buildPreviewUrl": "/build-preview/proj-xxx/v1.0.0/index.html",
  "buildStatus": "success",
  "buildLog": "...",
  "isCurrent": true,
  "createdAt": "2026-06-01T10:00:00.000Z",
  "updatedAt": "2026-06-01T10:05:00.000Z"
}
```

构建说明：

- 后端会先检测源码包内的前端应用根目录，再在该目录内构建。
- 有 `package.json` 且未传 `skipDocker=true` 时优先 Docker 构建；本机没有 Docker CLI 时会降级为宿主机构建。
- 传 `skipDocker=true` 时直接使用宿主机构建。
- 没有 `package.json` 时按静态源码处理。
- 构建输出目录按顺序查找：`dist/index.html`、`build/index.html`、`out/index.html`、应用根目录 `index.html`。

## 七、预览和静态资源

这些接口不在 `/api` 下，主要供 iframe 或浏览器直接打开。

### GET `/preview/runtime/:projectId`

打开项目源文件预览根入口。支持查询参数 `entry`，用于 module-shell 模式指定 JS 入口。

### GET `/preview/runtime/:projectId/*path`

打开项目源文件预览中的指定路径。

示例：

```text
GET /preview/runtime/proj-xxx/index.html
GET /preview/runtime/proj-xxx/__module_shell__.html?entry=src/main.js
```

### GET `/build-preview/:projectId/:sourceHash`

打开本地预览构建产物根入口。`sourceHash` 通常是 `preview-capability` 返回的构建缓存 key；交付构建产物也复用该路径形态，此时第二段通常是 `versionId`。

### GET `/build-preview/:projectId/:sourceHash/*path`

打开本地预览构建产物中的指定路径。

### GET `/preview/*path`

代理 Runtime 原始预览资源。

示例：

```text
GET /preview/ws-xxx
GET /preview/ws-xxx/index.html
```

### GET `/deploy/:projectId/latest/*path`

访问本地部署产物。该路径由 Express 静态资源服务提供，部署接口返回的 `deployUrl` 通常为：

```text
/deploy/proj-xxx/latest/index.html
```
