# AgentHub 业务后端接口文档

本文档按当前 `agentHubBackend` 的 NestJS Controller 和 DTO 整理，只记录已经实现的业务后端接口。

默认地址：

```text
业务后端: http://127.0.0.1:8790
AgentHub Runtime: http://127.0.0.1:8787
```

## 通用约定

- 所有 `/api/**` JSON 接口默认使用 `Content-Type: application/json`。
- 流式消息接口返回 `text/event-stream; charset=utf-8`。
- zip、预览、构建产物、部署产物接口返回文件或静态资源内容。
- 时间字段均为 ISO 字符串。
- 全局启用 Nest `ValidationPipe`，会自动转换查询参数类型，并拒绝 DTO 外的字段。
- 当前没有鉴权层。
- JSON 错误默认使用 Nest 结构，例如：

```json
{
  "message": "Project not found: proj-xxx",
  "error": "Not Found",
  "statusCode": 404
}
```

运行时 AgentHub 连接失败会返回 `503 Service Unavailable`；Runtime 已返回的非 2xx JSON 状态会按原状态码透传。

## 二、Agent 管理

Agent 接口由业务后端代理到 AgentHub Runtime。当前没有全局 Agent：每条 Agent 记录都必须归属某个 Runtime `workspaceId`，并绑定某个 `conversationId`。内置默认 Agent 也不是全局模板行，而是在创建群聊或单聊 conversation 时生成该 conversation 下的 Agent 实例。

- 全局 `/api/agents` 兼容保留，但不再作为读取或写入入口，调用会返回 `400`。
- 项目级 `/api/projects/:projectId/agents` 用于读取和管理某个项目绑定的 Runtime workspace Agent 列表。业务后端会直接透传 AgentHub Runtime 返回的工作区 Agent 数据；支持群聊创建、编辑、删除自建 Agent，也支持对默认 Agent 做当前工作区内的名称和模型调整。

当前 Agent 管理边界：

- 群聊工作区才允许创建工作区自建子 Agent。
- 单聊工作区固定绑定一个内置 Claude Code 或 Codex 直聊 Agent，不允许创建自建子 Agent。
- 单聊工作区的目标 Agent 只能是 `claude-code-direct` 或 `codex-direct`。
- 创建单聊时 Runtime 会在该 direct conversation 下创建对应的 `claude-code-direct` 或 `codex-direct` Agent 实例。
- 内置 Agent 不可删除，只能在当前工作区覆盖 `name`、`modelProvider`、`model`。
- 工作区自建 Agent 只属于当前群聊 workspace/conversation，创建、编辑、删除都不会影响其他 workspace 或 conversation。

Agent 常用字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | Agent ID。它是房间内的角色键，不是数据库全局唯一主键；创建自建 Agent 时可选，不传由 Runtime 生成。 |
| `name` | `string` | Agent 名称。 |
| `role` | `string` | 角色定位。 |
| `description` | `string` | 描述。 |
| `whenToUse` | `string` | 何时调用。 |
| `systemPrompt` | `string` | 系统提示词。 |
| `modelProvider` | `claude \| codex \| mock` | 模型提供方。 |
| `model` | `string` | 模型名，可选。 |
| `contextPolicy` | `object` | 上下文策略。 |
| `tools` | `string[]` | 工具列表。 |
| `permissions` | `object` | 文件、shell、网络、部署权限。 |
| `disallowedTools` | `string[]` | 禁用工具，可选。 |
| `permissionMode` | `readonly \| ask \| acceptEdits \| dangerous` | 权限模式。 |
| `runtimePolicy` | `object` | 运行策略。 |
| `outputSchema` | `string` | 输出约束。 |
| `isolation` | `shared \| worktree` | 隔离模式。 |
| `skills` | `string[]` | 技能列表。 |
| `routingProfile` | `object` | 路由画像，可选。 |
| `source` | `built-in \| workspace` | Agent 来源。 |
| `workspaceId` | `string` | Agent 所属 Runtime workspace。当前语义上必有。 |
| `conversationId` | `string` | Agent 所属 Runtime conversation。当前语义上必有。 |
| `createdAt` / `updatedAt` | `string` | 创建和更新时间。 |

## 三、项目级 Agent 管理

这些接口会先根据 `projectId` 找到业务项目绑定的 Runtime workspace，再代理到 Runtime 的 workspace Agent 接口。

### GET `/api/projects/:projectId/agents`

返回当前项目绑定的 Runtime workspace Agent 列表。

- 该接口当前直接返回 AgentHub Runtime `fetchWorkspaceAgents(workspaceId)` 的结果，业务后端不再额外按 conversation 做过滤。
- 返回内容以 Agent 服务实际返回为准；通常会包含当前 workspace 下的默认 Agent 展示形态，以及该群聊 workspace 内自建的 Agent。

响应：`AgentDefinition[]`。

### GET `/api/projects/:projectId/agents/:agentId`

返回当前项目 workspace 内的单个 Agent。

### POST `/api/projects/:projectId/agents`

在当前项目 workspace 内创建自建 Agent，并同步更新工作区群聊成员。

限制：

- 仅 `conversationType = group` 的项目允许调用该接口创建自建 Agent。
- `conversationType = direct` 的项目调用会返回 `400 Bad Request`。
- Runtime 直连接口 `POST /api/workspaces/:workspaceId/agents` 也会拒绝 `workspaceType = chat` 的工作区创建自建 Agent。

请求字段与 `CreateAgentDto` 一致，常用示例：

```json
{
  "id": "qa-agent",
  "name": "测试专家",
  "role": "QA Engineer",
  "description": "负责测试和验收",
  "whenToUse": "需要测试、验收或质量把关时调用",
  "systemPrompt": "你是一个严格的软件测试专家。",
  "modelProvider": "codex",
  "model": "default",
  "permissions": {
    "fileRead": true,
    "fileWrite": false,
    "shell": false,
    "webSearch": false,
    "webFetch": false,
    "deploy": false
  }
}
```

必填字段：`name`、`systemPrompt`。

单聊工作区错误示例：

```json
{
  "message": "Custom agents can only be added to group workspaces.",
  "error": "Bad Request",
  "statusCode": 400
}
```

响应：创建后的 AgentDefinition，通常包含：

```json
{
  "id": "qa-agent",
  "name": "测试专家",
  "source": "workspace",
  "workspaceId": "ws-xxx",
  "createdAt": "2026-06-01T10:00:00.000Z",
  "updatedAt": "2026-06-01T10:00:00.000Z"
}
```

### PATCH `/api/projects/:projectId/agents/:agentId`

编辑当前项目 workspace 内的 Agent。

内置 Agent 在工作区内只支持覆盖这些字段：

```text
name, modelProvider, model
```

工作区自建 Agent 支持编辑：

```text
name, modelProvider, model, role, description, whenToUse, systemPrompt,
contextPolicy, tools, permissions, disallowedTools, permissionMode,
runtimePolicy, outputSchema, isolation, skills, routingProfile
```

响应：更新后的 AgentDefinition。

### DELETE `/api/projects/:projectId/agents/:agentId`

删除当前项目 workspace 内的自建 Agent，并同步更新工作区群聊成员。

响应：

```json
{
  "deleted": true,
  "agentId": "qa-agent",
  "workspaceId": "ws-xxx"
}
```

限制：内置 Agent 不可删除。

内置 Agent 删除错误示例：

```json
{
  "error": "Built-in agent cannot be deleted: engineer"
}
```

### POST `/api/projects`

创建业务项目，并创建或绑定 Runtime workspace。

请求：

```json
{
  "name": "投票小程序",
  "goal": "做一个候选人投票系统",
  "workspaceType": "dev",
  "conversationType": "group",
  "agentIds": ["product-manager", "engineer", "reviewer"],
  "workspaceId": "ws-existing",
  "conversationId": "conv-existing"
}
```

字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | `string` | 是 | 项目名称，最长 120。 |
| `goal` | `string` | 是 | 项目目标，最长 4000。 |
| `workspaceType` | `dev \| research \| writing \| chat` | 否 | 默认 `dev`。直接单聊时会规范为 `chat`。 |
| `conversationType` | `group \| direct` | 否 | 默认 `group`。 |
| `agentIds` | `string[]` | 否 | 直接单聊时取第一个 Agent；不传默认 `codex-direct`。群聊当前由 Runtime 自动加入默认内置成员，该字段不用于选择群聊成员。 |
| `workspaceId` | `string` | 否 | 绑定已有 Runtime workspace。传入后不会新建 workspace。 |
| `conversationId` | `string` | 否 | 绑定已有 Runtime conversation。 |

创建群聊工作区示例：

```json
{
  "name": "投票小程序",
  "goal": "做一个候选人投票系统",
  "workspaceType": "dev",
  "conversationType": "group"
}
```

创建单聊工作区示例：

```json
{
  "name": "和 Codex 对话",
  "goal": "聚焦实现一个 React 组件",
  "workspaceType": "chat",
  "conversationType": "direct",
  "agentIds": ["codex-direct"]
}
```

单聊工作区规则：

- 只能绑定一个目标 Agent。
- 目标 Agent 只能是内置直聊 Agent：`claude-code-direct` 或 `codex-direct`。
- 客户端应只暴露“Claude Code Agent”和“Codex Agent”两个单聊入口，并分别传入 `claude-code-direct`、`codex-direct`。
- 如果传入自建 Agent、未知 Agent，或其他内置群聊 Agent，会返回 `400 Bad Request`。

单聊目标非法错误示例：

```json
{
  "message": "Direct workspaces can only talk to built-in Claude Code or Codex direct agents.",
  "error": "Bad Request",
  "statusCode": 400
}
```

响应：ProjectResponse。

## 五、项目运行态、文件和消息

### GET `/api/projects/:projectId/state`

获取单个项目对应 workspace 的前端聚合状态。

查询参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `messagePageSize` | `number` | `40` | 单页消息数量，最大 200。 |
| `messageCursor` | `string` | 无 | 更早消息页游标；首次请求不传，后续传上一次响应里的 `messagePage.nextCursor`。 |
| `messageLimit` | `number` | `40` | 兼容旧参数，等价于不传 cursor 时的 `messagePageSize`。 |

响应：

```json
{
  "state": {
    "workspaces": [],
    "conversations": [],
    "messages": [],
    "agents": [],
    "workspaceAgentMembers": [],
    "agentSessions": [],
    "agentSessionMessages": [],
    "taskHandoffs": [],
    "agentRuns": [],
    "artifacts": [],
    "changeSets": [],
    "contextSnapshots": [],
    "workflowEvents": [],
    "diagnosticLogs": []
  },
  "messagePage": {
    "limit": 40,
    "total": 120,
    "hasMore": true,
    "nextCursor": "eyJvZmZzZXQiOjgwfQ",
    "offset": 80,
    "endOffset": 120
  }
}
```

说明：

- `state` 是 Runtime 全局状态过滤到当前项目 workspace 后的结果。
- `state.workspaces[]` 会补充 `projectId`、`agentHubPreviewUrl`、`agentHubZipUrl`、`pinnedAt`、`archivedAt`。
- `state.messages[]` 会追加业务后端合成的本地交付系统消息，例如源码版本保存、交付构建完成或本地部署完成。
- `state.artifacts[]` 会追加业务后端合成的本地交付 artifact，例如源码 zip、构建预览和本地部署入口。
- `state.agents[]` 返回当前 workspace/conversation 可见的 Agent；每条 Agent 都带 `workspaceId` 和 `conversationId`，不存在全局 Agent 行。
- `state.messages[]` 按时间正序返回当前页；首次请求返回最新一页，上拉历史时传 `messagePage.nextCursor`。
- `state.workflowEvents[]` 会按当前分页内可见消息/turn 做过滤，避免前端一次性读取过多历史事件。
- `state.workspaceAgentMembers[]` 是当前 workspace 的 Agent 成员关系，用于恢复默认 Agent 的名称、模型覆盖和排序状态；实际 Agent 定义仍以 `state.agents[]` 的 scoped 记录为准。
- 当前没有单独的会话列表、消息历史、事件历史接口；前端从 `state` 读取这些数据。

```json
    "status": "ready",
```

`sourceArchive`、`build`、`deployment` 的 `status` 枚举：

- `deployment` 总是取项目部署记录中 `createdAt` 最新的一条。

### POST `/api/projects/:projectId/preview-build?force=true`

启动或重试本地预览构建。当前会立即返回最新 `preview-capability` 快照，构建在后台继续执行。

查询参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `force` | `boolean` | `false` | 是否强制重新构建。 |

响应：同 `GET /api/projects/:projectId/preview-capability`。

说明：

- 仅 `mode=build` 且构建工具识别为 Vite 时会真正启动后台构建；其他模式会直接返回当前 capability。

- 构建并发上限由后端控制，排队时 `build.summary` 会显示等待构建槽。

### POST `/api/projects/:projectId/builds`

构建指定版本。当前接口是同步执行，不是异步 job 列表接口；成功或失败都会回写版本的构建字段。

请求：

```json
{
  "versionId": "v1.0.0",
  "skipDocker": false,
  "installCommand": "npm install",
  "buildCommand": "npm run build"
}
```

字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `versionId` | `string` | 否 | 不传时使用 `currentVersionId`。 |
| `skipDocker` | `boolean` | 否 | 为 `true` 时跳过 Docker 容器构建，改用宿主机执行安装和构建命令。 |
| `installCommand` | `string` | 否 | 安装命令。Docker 构建默认 `npm install`；宿主机构建会按 lockfile 推断，兜底 `npm install`。 |
| `buildCommand` | `string` | 否 | 构建命令，默认 `npm run build`。 |

响应：更新后的 ProjectVersionRecord。

```json
{
  "versionId": "v1.0.0",
  "tag": "v1.0.0",
  "commitSha": "abc123",
  "sourceZipUrl": "/api/projects/proj-xxx/source.zip?versionId=v1.0.0",
  "buildPath": "D:\\...\\data\\artifacts\\build\\proj-xxx\\v1.0.0",
  "buildPreviewUrl": "/build-preview/proj-xxx/v1.0.0/index.html",
  "buildStatus": "success",
  "buildLog": "...",
  "isCurrent": true,
  "createdAt": "2026-06-01T10:00:00.000Z",
  "updatedAt": "2026-06-01T10:05:00.000Z"
}
```

构建说明：

- 后端会先检测源码包内的前端应用根目录，再在该目录内构建。
- 有 `package.json` 且未传 `skipDocker=true` 时优先 Docker 构建；本机没有 Docker CLI 时会降级为宿主机构建。
- 传 `skipDocker=true` 时直接使用宿主机构建。
- 宿主机构建默认安装命令会按 lockfile 推断：`pnpm-lock.yaml` 使用 `pnpm install --frozen-lockfile --prefer-offline`，`package-lock.json` 使用 `npm ci`，`yarn.lock` 使用 `yarn install --frozen-lockfile`，否则使用 `npm install`。
- 没有 `package.json` 时按静态源码处理。
- 构建输出目录按顺序查找：`dist/index.html`、`build/index.html`、`out/index.html`、应用根目录 `index.html`。
- 构建成功后会复制产物到 `data/artifacts/build/:projectId/:versionId`，并返回 `/build-preview/:projectId/:versionId/index.html`。
- 构建失败也会回写该版本的 `buildStatus=failed` 和 `buildLog`，接口本身返回对应错误。

## 七、预览和静态资源

这些接口不在 `/api` 下，主要供 iframe 或浏览器直接打开。

打开项目源文件预览根入口。支持查询参数 `entry`，用于 module-shell 模式指定 JS 入口。

打开项目源文件预览中的指定路径。


打开本地预览构建产物根入口。`sourceHash` 通常是 `preview-capability` 返回的构建缓存 key；交付构建产物也复用该路径形态，此时第二段通常是 `versionId`。

### GET `/build-preview/:projectId/:sourceHash/*path`

打开本地预览构建产物中的指定路径。

### GET `/preview/*path`

代理 Runtime 原始预览资源。

示例：

```text
GET /preview/ws-xxx
GET /preview/ws-xxx/index.html
```

### GET `/deploy/:projectId/latest/*path`

访问本地部署产物。该路径由 Express 静态资源服务提供，部署接口返回的 `deployUrl` 通常为：

